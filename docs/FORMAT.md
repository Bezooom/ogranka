# Почему по умолчанию не FACETED_BREP

Запрос был на ASCII-грань с полной рёберной цепочкой: точка, вершина, направление, вектор, линия, `EDGE_CURVE`, `ORIENTED_EDGE`, `EDGE_LOOP`, плоскость, грань, оболочка, тело.

`FACETED_BREP` такую цепочку не принимает: его границы описаны `POLY_LOOP`, а рёберных сущностей в нём нет. Поэтому по умолчанию писатель отдаёт рёберную форму. Компактная форма включается ключом `--faceted` и описана ниже.

Проверено на FreeCAD 1.1.1:

- оболочка из голых `FACE_OUTER_BOUND` внутри `FACETED_BREP` читается как оболочки без граней: 23 628 `shells`, 0 `solids`, 0 `faces`;
- та же геометрия с `ADVANCED_FACE` + `PLANE` + `FACE_OUTER_BOUND`/`POLY_LOOP` читается как тела: 23 628 `solids`, 141 768 граней, `closed`, `valid`.

Поэтому компактная форма оставляет `ADVANCED_FACE` и плоскость, но убирает вершины, рёбра, линии, векторы и `EDGE_LOOP`: 53.8 МБ против 129.5 МБ рёберной схемы на 23 628 телах.

Писатель по умолчанию отдаёт форму, которую уже открывают и FreeCAD, и SolidWorks:

- `FILE_SCHEMA(('AUTOMOTIVE_DESIGN'))`, как в файлах SolidWorks и в OCC `cube.stp`;
- цепочка продукта: `APPLICATION_PROTOCOL_DEFINITION` → `MECHANICAL_CONTEXT` → `PRODUCT` → `ADVANCED_BREP_SHAPE_REPRESENTATION`;
- первый item представления – `AXIS2_PLACEMENT_3D`;
- тело – `MANIFOLD_SOLID_BREP` (родитель `FACETED_BREP`) с `CLOSED_SHELL` и `ADVANCED_FACE` / `PLANE`;
- единицы – `SI_UNIT(.MILLI.,.METRE.)`.

`MANIFOLD_SOLID_BREP` здесь не «другой формат вместо граней». Грани плоские, рёбра прямые, общие вершины склеены с допуском 1e-4 мм. Отличие только в том, что граница грани – рёберная петля, а не `POLY_LOOP`.

Ориентир по заголовку и цепочке продукта: [OCC cube.stp](https://github.com/jeromerobert/jCAE/blob/master/occjava/test/input/cube.stp). Этот репозиторий не проверял, что наш файл открывается тем же импортером. Совпадение заголовка – решение по опубликованному примеру, не результат прогона FreeCAD.

Незамкнутая сетка не притворяется телом: пишется `OPEN_SHELL` и предупреждение. Внутренняя полость, не сквозное отверстие, пишется как `BREP_WITH_VOIDS`. Сквозное отверстие остаётся одной оболочкой с `FACE_BOUND`.

# Размер файла

Замер на 23 628 телах-коробках (141 768 граней), та же машина:

| Форма | Размер | Запись |
| --- | --- | --- |
| Рёберная схема по умолчанию | 129.5 МБ | 3.2 с |
| `--faceted` | 53.8 МБ | 1.2 с |
| STEP от Open CASCADE 7.8 на модели коллеги (146 065 граней, 23 628 тел) | 488 МБ | – |

Перевес OCC дают сущности на каждое ребро каждой грани: в том файле 597 518 `PCURVE`, столько же `DEFINITIONAL_REPRESENTATION`, 84 681 `B_SPLINE_CURVE_WITH_KNOTS`, 13 640 `SEAM_CURVE`. Наш писатель ничего из этого не пишет: грани плоские, рёбра прямые, параметрические кривые не нужны.

Компактная форма не применяется к телу, у которого в грани есть отверстие или есть полость: такая оболочка остаётся рёберной, потому что `POLY_LOOP` не несёт внутреннюю границу в этой схеме.
